# 资金ETF流动每日跟踪

面向客户的 A 股 ETF 日报网站。系统只使用真实公开数据，每个工作日上午在交易所完成上一交易日清算数据发布后自动更新；GitHub Pages 与 Render 共用同一份静态构建产物。

## 日报回答什么

- 今日盘面：已完成分析的 A 股股票 ETF 估算净申赎、流入/流出方向、风格与行业切换，给出精简结论。
- 宽基体系：覆盖上证、沪深、中证、深证、创业板与科创板主要宽基系列的 1/5/20 日资金摘要；规则表可每日识别新产品，并把未命中的新 ETF 列入待归类清单。
- 两张坐标图：横轴为 20 日相对沪深300收益，纵轴为 5 日资金变化率（5 日估算净申赎占 5 日前规模的百分比），分别观察宽基/风格与行业板块。
- 客观补充：价格—资金状态、份额增加/减少ETF只数、单只ETF贡献集中度与数据质量。
- 客户交付：手机端适配，支持 2.5 倍像素密度导出高清 JPG。

## 数据与口径

| 字段 | 主源 | 用途 |
| --- | --- | --- |
| 沪市 ETF 日终份额 | 上海证券交易所，AKShare 固定版本采集 | 份额变化 |
| 深市 ETF 日终份额 | 深圳证券交易所，AKShare 固定版本采集 | 份额变化 |
| T 日单位净值 | 东方财富公开基金净值，AKShare 采集 | 估算申赎金额 |
| ETF 收盘价 | 新浪公开行情，AKShare 采集 | 1/5/20 日收益代理 |

`估算净申赎 =（期末份额 − 期初份额）× 期末已验证单位净值`。金额用于观察方向与量级，不等同基金公司的最终现金流。公开份额不包含投资者身份，因此系统不会推断“国家队”、机构、个人或做市商。

系统每天保存交易所全部 ETF 名册，不因产品类型或分类状态丢弃 ETF，并与前一交易日按代码核对新增、消失和名称变化。资金分析只使用历史、净值和分类均完整的 A 股股票 ETF；每只 ETF 只进入一个主要分析组，避免重复计算。分类规则保存在 `data_pipeline/classification.json`，可人工审计。完整名册另存于 `site/data/universe/`。

## 自动更新

`.github/workflows/daily-etf-data.yml` 在下一交易日盘前 07:30、08:00、08:30 和 09:00（Asia/Shanghai）自动检查。任务按周二至周六运行，以覆盖周一至周五的收盘份额：

1. 执行数据管道单元测试。
2. 优先检查自然日当天；若交易所尚未发布完整日终份额，则自动回退至最近完整交易日。获取最近 21 个真实交易日份额、当日净值与组别收益代理。
3. 执行全量 ETF 数量及分交易所日变动、重复代码、空字段、分类覆盖、历史窗口和收益代理覆盖检查。
4. 构建并运行前端测试；失败时不覆盖上一份已验证快照。
5. 仅在发现新的完整交易日时，提交 `site/data/latest.json`、`site/data/universe/` 全量名册和按日期归档的历史快照，触发 Render 自动部署。

页面的日期范围是滚动窗口。每发布一个新的完整交易日，结束日更新为该交易日，开始日同步前移，始终保留 21 个交易日（用于计算 1/5/20 日变化）。自然日已经进入新一天，不代表交易所已经发布该日的日终份额；网站明确显示的是“数据交易日”，不会伪装成自然日实时数据。

客户发送制度：页面观点日期始终等于份额统计交易日。例如 2026-08-14 早上取得 2026-08-13 完整数据，标题写“2026年8月13日 ETF跟踪观点”，作为 2026-08-14 盘前材料发送，建议在 09:10 前完成。若 09:10 前官方数据仍未完整发布，应继续显示上一份已验证观点并明确其数据交易日，不得把旧数据改写成当日观点。

手工指定交易日：

```powershell
python data_pipeline/update_daily.py --date 2026-08-12
```

## 本地验证

```powershell
pip install -r data_pipeline/requirements.txt
python -m unittest discover -s data_pipeline -p "test_*.py"
npm ci
npm test
```

## Render

仓库根目录 `render.yaml` 已绑定 `main` 分支：

- Build Command: `npm ci && npm run build`
- Publish Directory: `dist`
- Auto Deploy: commit

在 Render 选择 **New → Blueprint** 并授权本仓库即可。之后 GitHub 每次验证通过的提交都会自动发布。
