# 资金ETF流动每日跟踪

面向研究与机构客户的 A 股 ETF 资金跟踪系统。系统以**沪深交易所ETF日终份额**为一级市场核心事实，以**同一交易日单位净值**估算净申购/赎回金额；所有客户端模块、JSON、结论、测试和自动任务统一遵守 **Data Contract 7.0**。

> 核心原则：同一个经济变量只有一个定义、一个主字段、一个统计范围和一套措辞。任何缺失、歧义或无法对账的数据宁可不发布，也不使用其他指标替代。

## 1. 首页核心指标

### A股股票ETF当日一级市场净申购/赎回金额估算

唯一主公式：

```text
PrimaryFlow1d
= (T日交易所清算后份额 - T-1日公司行动调整后的可比份额)
  × T日单位净值
```

金额单位统一为亿元。

- 正值：净申购估算。
- 负值：净赎回估算。
- T-1只用于构造T日可比份额基准，不是“上一日资金流”。
- 成交均价估值仅用于外部口径对照，绝不覆盖主口径。
- 二级市场成交方向指标与一级市场净申购/赎回是不同经济变量，绝不互相替代或校准。

## 2. 份额方向只数

所有模块只使用一个字段：`shareDirection1d`。

```text
increase   = 份额增加
decrease   = 份额减少
unchanged  = 份额不变
```

为消除公司行动换算和浮点计算留下的机器噪声，绝对份额差小于 `0.5份` 时统一视为不变。市场总量、资产类别、研究分组和审计不得各自重新判断正负。

## 3. 5日 / 20日：累计与端点严格分开

系统同时保留两个不同概念，禁止混称。

### 逐日累计净申购/赎回

```text
Flow5dCumulative  = 最近5个已验证交易日 sum(PrimaryFlow1d)
Flow20dCumulative = 最近20个已验证交易日 sum(PrimaryFlow1d)
```

只有对应交易日的每日一级市场事实全部存在时才发布。历史不足时客户端显示“数据积累中”，不使用端点估算补位。

### 端点份额变化金额估算

```text
Flow5dEndpoint
= (T日份额 - 5个交易日前可比份额) × T日NAV

Flow20dEndpoint
= (T日份额 - 20个交易日前可比份额) × T日NAV
```

端点指标用于观察份额存量变化和价格×份额坐标，不属于逐日资金流之和，因此任何页面、结论和文档都不得把它称为“5日/20日累计资金流”。

## 4. 二级市场成交统计

二级市场单独保存两类交易统计，均不属于ETF一级市场申购/赎回。

### 主动成交方向差额（估算）

使用东方财富同日ETF行情中的成交额、外盘和内盘：

```text
主动买入成交额估算 = 成交额 × 外盘 / (外盘 + 内盘)
主动卖出成交额估算 = 成交额 × 内盘 / (外盘 + 内盘)
主动成交方向差额 = 主动买入估算 - 主动卖出估算
```

这是主动成交方向的启发式统计。**它不代表市场净新增资金，不得称为ETF资金净流入/净流出。**

### 行情商“主力净额”字段

东方财富“主力净流入-净额”作为行情商定义的另一项交易统计原样留存。系统明确标识其来源和经济含义，不将其用于校准一级市场净申购/赎回。

## 5. 统计范围

一级市场同时保存三个可比较范围：

- `allEtf`：全部可验证场内ETF。
- `stockEtfIncludingCrossBorder`：股票ETF，含跨境股票ETF。
- `aShareStockEtf`：仅A股股票ETF，是首页主指标。

全部ETF另拆成六个互斥资产类别：

- A股股票ETF
- 跨境股票ETF
- 债券ETF
- 货币ETF
- 商品ETF
- 其他ETF

六类数量与资金金额必须对账回 `allEtf`；任一差异超过审计容忍度即禁止发布。

## 6. 数据源与溯源

### 一级市场份额：主事实

- 上海证券交易所ETF日终份额。
- 深圳证券交易所ETF日终份额。
- AKShare仅作为公开接口适配层，不改变交易所数据的经济含义。
- 第三方“最新份额”只用于交叉检查，绝不得覆盖交易所份额。

### NAV与基金类型

- 使用精确目标交易日的ETF单位净值和基金类型面板。
- 查询日期必须与 `tradeDate` 完全一致；禁止用最新值跨日回填。
- NAV用于一级市场金额主估值；基金类型用于资产范围识别。

### 成交均价对照

- 东方财富同日ETF行情。
- 仅用于复现采用成交均价估值的外部资讯口径。
- 不覆盖同日NAV主口径。

### 二级市场成交方向

- 东方财富同日ETF行情中的成交额、外盘、内盘以及行情商“主力净额”字段。
- 与一级市场数据分开落盘、分开命名、分开解释。

每份 Contract 7.0 快照均包含 `provenance`，明确记录每类数据的来源、用途与时点规则。

## 7. 公司行动与异常保护

ETF拆分、合并、份额单位调整会制造巨大伪申购/赎回。生产系统：

1. 先保留交易所官方T日份额，不允许第三方份额覆盖。
2. 检测接近 2、3、4、5、1/2、1/3 等合理份额比例的跳变。
3. 优先使用精确交易日NAV的反向比例变化确认公司行动；NAV不可用时才使用价格辅助确认。
4. 将历史份额调整到与T日相同的份额单位后再计算净申购/赎回。
5. 无法解释的超大单ETF变化、全市场份额单位异常、日期错位或接口schema变化均触发 fail-closed，禁止发布。

588710 的历史1:3份额单位调整继续作为回归测试样本。

## 8. ETF分类：市场总量与研究分组分离

### 市场总量

只要ETF属于A股股票ETF并具备可验证份额/NAV，就进入A股股票ETF市场总量；**是否成功分类不得影响市场总量。**

### 研究分组

宽基、风格、行业和主题用于资金轮动研究。当前主要依赖基金名称规则，因此系统不把它包装成基金管理人、指数公司或申万官方分类。

- 明确名称：进入唯一研究组，避免重复计数。
- 泛化关键词或无法唯一判断暴露方向：`classificationStatus = ambiguous`。
- ambiguous ETF继续留在A股股票ETF市场总量，但不进入分组排名和客户端分组结论。
- `510150 消费ETF招商` 等已知泛化匹配案例设有回归保护，不能仅凭“消费”二字宣称属于食品饮料。

长期最优升级方向是建立“ETF代码 → 跟踪指数代码 → 指数名称 → 研究分类”的显式主数据表；在该主数据完成以前，系统优先准确率，不以错误归类换覆盖率。

## 9. 价格 × 份额坐标

当前价格端使用各研究组的**代表ETF**作为价格代理，因此客户端必须明确写“代表ETF价格代理”，不能写成该行业/主题官方指数收益。

- 横轴：代表ETF近20日相对沪深300收益。
- 纵轴：组内ETF 5日端点份额变化金额估算 ÷ 5日前参考规模。

该图是“价格代理 × 端点份额变化”研究工具，**不是“指数收益 × 5日累计资金流”。**

## 10. 客户结论生成边界

自动结论只允许陈述可由当前快照直接证明的事实：

- A股股票ETF一级市场当日净申购/赎回金额估算。
- ETF份额增加/减少/不变只数。
- 宽基、行业/主题研究组的一日净申购/赎回估算排序。
- 单只ETF最大净申购/赎回估算。

自动结论不得：

- 把二级市场成交方向写成资金净流入/净流出。
- 把端点变化写成累计资金流。
- 把研究分组写成官方申万分类。
- 从份额变化直接推断投资者真实意图、未来价格、国家队行为或投资建议。

## 12. 数据文件

- `site/data/latest.json`：最新已验证完整快照。
- `site/data/history/YYYY-MM-DD.json`：完整历史快照。
- `site/data/daily/YYYY-MM-DD.json`：每日一级市场事实，用于真实5/20日逐日累计。
- `site/data/order_flow/YYYY-MM-DD.json`：同日二级市场成交方向事实。
- `site/data/universe/`：交易所完整ETF名册与每日变化审计。
- `data_pipeline/classification.json`：名称规则研究分类。
- `data_pipeline/system_contract_v7.py`：统一经济含义、统计范围、累计逻辑、分类边界、结论与溯源契约。
- `data_pipeline/contract_finalizer_v7.py`：端点方向只数与价格×份额状态的最终确定性归一化。
- `data_pipeline/audit_snapshot_v7.py`：外发前 fail-closed 审计。

## 14. 发布原则

系统追求的是**可定义、可复算、可对账、可追溯**，而不是声称任何公开数据系统能够达到数学意义上的“永不出错”。Contract 7.0 的工程要求是：发现不一致时必须显式失败，而不是静默猜测、补值或改口径。
